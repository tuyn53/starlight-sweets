# 甜星大作战 SWEET STAR BLITZ · 关卡循环修正设计

> 状态：**设计已拍板（2026-11-19）**，未改代码。
>
> **拍板结论**：① 每关都有关底（5/10/15/20 主题 Boss，其余关为两阶段守卫）；② 单关目标 8-10 分钟达成 Lv20；③ 关卡之间完全不继承数值，跨关成长只靠解锁新卡/新怪。
>
> 关联：`docs/内容扩展设计.md`（解锁表语义需随之调整，见第 9 节）
> 最后更新：2026-11-19

## 1. 诊断：现在的关卡和你最初要的不是一回事

你要的循环：**进关 → 从 Lv1 练到 Lv20 满级 → 满级解锁 Boss 战 → 打完过关**。

代码里的实际规则（`js/logic.js`）：

| 位置 | 实际实现 | 后果 |
|---|---|---|
| logic.js:328-331 | 普通关过关 = `存活 ≥ 30+关卡×1.6 秒` **且** `击杀 ≥ 18+关卡×2 只` | 第 1 关只要 31.6 秒 + 20 杀就过，30 秒刷一波就完事 |
| logic.js:314 | Boss 关开场 **2.2 秒**就召唤 Boss | 玩家还是 Lv1，Boss 直接来，没有"练级→决战"的铺垫 |
| logic.js:251-261 | `gainXp` 里 `player.level++` **没有任何上限** | 根本没有"20 级满级"这个概念，关卡和等级完全脱钩 |
| logic.js:48-57 | 每关起跑线送属性：`+10HP/关`、`+10%伤害/关`、按关号白送 2-4 把武器 | "从 1 级开始"是假的，一进关就已经是高配状态 |
| logic.js:70 | 敌人强度含 `(player.level-1)*0.04` | 等级只影响怪强度，不影响关卡进程 |

**结论**：上一版"关卡制"改造时，把关卡做成了"30 秒一局的短关卡"，丢掉了原版单局长跑（1→20 级）的核心节奏。要修的不是手感，是关卡骨架。

## 2. 目标循环（修正后）

```
进入第 N 关（Lv1，只有 1 把星芒）
  → 刷怪 / 拾取 / 升级三选一（卡池 = 已解锁武器+被动）
  → 达到 Lv20 满级（约 8-10 分钟）
  → "星光满溢"清场演出
  → Boss 降临
  → 击杀 Boss → 过关结算 → 解锁 N+1
（死亡 = 本关失败，可从 N 重开）
```

**关卡之间的成长只发生在"卡池/怪物/场景/Boss"上，不继承数值。** 这是 roguelite 的标准结构，也正好接上《内容扩展设计》的"按幕解锁新卡/新怪"。

## 3. 关内时间轴（10 分钟模板）

| 时间 | 玩家等级 | 内容节奏 |
|---|---|---|
| 0:00-0:45 | 1-3 | 最基础 2-3 种怪，密度低，给玩家建立走位 |
| 0:45-2:30 | 4-8 | 第 2 波怪入场（本关第一次新面孔提示），首只精英 |
| 2:30-5:00 | 9-13 | 第 3 波怪 + 密度抬升，精英间隔缩短 |
| 5:00-7:30 | 14-19 | 高压期：混合波次 + 双精英，考验构筑成型 |
| 7:30-8:30 | 20 | 满级 → 清场 → Boss 降临（约 3 秒演出） |
| 8:30-10:00 | 20 | Boss 战（守卫 40-60 秒 / 主题 Boss 60-90 秒） |

**满级即停经验**：Lv20 后经验球不再掉落（或转为微量回血），避免"满级还在捡垃圾"。

## 4. 触发规则（伪代码，落实现时照这个写）

```
if (player.level >= CFG.LEVEL.playerMax && !game.bossSpawned && state === 'playing') {
  beginBossSequence();   // 清场 + 震屏 + 星光演出 + toast
  spawnBoss();           // 主题关 = 主题 Boss；普通关 = 关底守卫
}
```

- `CFG.LEVEL.playerMax = 20`（新增）
- 普通关不再有"存活/击杀"过关判定，`levelTargets()` 整段废弃
- Boss 死亡 → `levelClear()`（现有逻辑不用改）
- 普通关的"关底守卫"用 `boss` 机制但两阶段、血量 60%、无激光（见第 6 节）

## 6. Boss / 守卫

| 类型 | 血量 | 阶段 | 说明 |
|---|---|---|---|
| 主题 Boss（5/10/15/20） | `5000 + 关卡×500`（L20≈15000） | 三阶段：12 向弹幕 → 弹幕+召唤 → 蓄力激光 | 沿用现有 mech，加各自 twist（抹茶减速池/云朵风推/黑森林四阶段） |
| 关底守卫（其余 16 关） | `2400 + 关卡×220` | 两阶段：弹幕 → 弹幕+召唤 | 复用 boss 图 + hue 染色 + "守卫"前缀，血量与阶段降配 |

Boss 战目标时长 40-90 秒。现公式 `900+关卡×180`（L20 才 4500）在满级构筑面前 5 秒就没了，必须上调。

## 7. 数值配平（建议起点，需 3 次试跑校准）

| 参数 | 现值 | 建议 | 理由 |
|---|---|---|---|
| `XP_GROW` | 1.15 | **1.18** | 单局击杀量从 ~300 升到 500-700，曲线要相应变陡，总量 ≈800-900 XP 到 Lv20 |
| 刷怪间隔 | `0.85×0.987^t`，min 0.17，batch 随 t 涨到 7 | **改为"维持屏幕数量"模型**：目标存活数 `22 + 玩家等级×3`（上限 80），每秒最多补 6 只 | 现模型后期每秒几十只直接顶到 MAX_ENEMIES=220，既卡又乱 |
| 敌人成长 | `1 + time×0.011 + (关-1)×0.16 + (玩家等级-1)×0.04` | `1 + (关-1)×0.15 + time×0.004 + (玩家等级-1)×0.030` | 现在 time 系数 0.011 在 10 分钟时是 +6.6 倍，压死玩家构筑；改由关卡号和等级主导 |
| 起跑线加成 | +HP/+伤害/白送武器 | **全部删除**，每关都是 Lv1 + 1 把星芒 | 这是"从 1 级练起"的前提；难度只靠敌人与卡池深度 |
| `MAX_ENEMIES` | 220 | 建议降到 **120** | 屏幕 80 只 + 分裂/召唤余量足够，移动端更稳 |

## 8. UI / 结算 / 失败

- HUD：把关卡目标文案从"存活 xx 秒 / 击杀 xx"改成 **等级进度 `Lv 12 / 20`** + 经验条；满级后进度条变"星光满溢"并提示 Boss 来袭。
- 结算面板：显示 **用时 / 达成等级 / 击杀数 / 最终构筑（武器+被动清单）**。
- 失败：死亡 → 本关失败，按钮"重试本关 / 返回选关"。
- 存档：仍只存解锁关号，不需要存中间态。

## 9. 与《内容扩展设计》的衔接

- 原解锁表的语义从"每关只新增一种怪、30 秒一局"改为"**每关扩充可用池**"（第 5 节已重写）。
- 卡池按幕解锁的规则不变，反而更重要了：因为关卡之间不继承数值，**幕解锁新卡就是唯一的跨关成长感**。

## 11. 验收标准

- 第 1 关：不刷到 Lv20 绝不过关；满级后 3 秒内 Boss 降临；击杀方可过关。
- 单关用时 8-12 分钟（Lv20 在 7:30-8:30 达成）。
- 5/10/15/20 关 Boss 战 60-90 秒；其余关守卫 40-60 秒。
- 第 1 关与第 20 关起手完全一致（Lv1 + 星芒一把），差异只体现在怪池/卡池/数值。
- 20 关连续通关总时长约 3.5-4 小时。
