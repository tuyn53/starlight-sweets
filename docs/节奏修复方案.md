# 甜星大作战 · 节奏修复方案（机枢 · 证据化设计契约版）

> 状态：**可采纳**（采纳门槛六项齐全，见 §6）。
> 痛点：老大试玩反馈"一下子就打过关、打几个怪就升级、左脚踩右脚登天"。
> 方法：game-design-contracts（归因门 / 单变量释放 / 决策与证据）+ 网络对标（VS Wiki、teemo.dev、GameDev StackExchange）。
> 最后更新：2026-11-19

---

## 0. 结论先行

**你的游戏不需要"去掉雪球"——雪球是幸存者类的核心爽点。你的问题是雪球拐点来得太早：2.4 分钟就满级，而目标是 8-10 分钟。**

归因结果（判别性探针，见 §3）：**主瓶颈 = 经验曲线形状**，不是敌血联动、不是前期流量。之前判断的"给敌血装刹车"经模拟证明是次要旋钮，已否决。

修复分 3 批，每批只放 1-2 个变量，带验收门和回滚条件。**不是一次性全改**——一次全改出了问题无法归因。

## 4. 修复方案：三批施工图（每批 ≤2 变量）

### 批次 1 — 改经验曲线形状（主瓶颈，先做）

```yaml
current_rung: UL-L1
released_this_round:
  - variable: "xpNext 公式：从 5×1.18^(lv-1)+lv 改为分段线性"
    reason: "归因确认曲线形状为主瓶颈"
    expected_learning: "满级时间能否从 2.4 分钟进入 6-10 分钟带"
held_constant:
  - "CFG.SPAWN 维持数量模型参数不动"
  - "diffLv=0.03 / diffTime=0.004 不动"
  - "UNLOCK_TABLE 怪池与波次不动"
  - "武器/被动数据表不动"
  - "满级触发关底的逻辑不动"
preregistered_signals:
  pass: ["模拟满级时间 ∈ [6,10] 分钟", "前 5 级累计经验占总量比例从 6% 升到 ≥15%"]
  fail: ["模拟满级时间 <5 分钟", "或 >12 分钟"]
  confounded: ["同期动了刷怪或敌血参数"]
  stop: ["出现卡死：经验需求 ≥1000/级导致永远升不满"]
rollback: "xpNext 公式还原为 5×1.18^(lv-1)+lv"
stop_rule: "任一 stop 信号出现立刻停"
fallback_rung: UL-L0
```

**目标公式**（建议值，来自探针中"陡线性 10+15×lv"命中 8.6 分钟）：
```
xpNext(lv) = 10 + 15*(lv-1)      // L1→2 需 10 XP，L19→20 需 280 XP，累计约 2760
```
- 边界：L1→2 从 6 XP 抬到 10（消除"打几个怪就升级"）；累计从 796 抬到 ~2760（VS 到 20 级是 1805，我们偏高，因我们只有 19 次升级而 VS 到 20 级只是前段）。
- ⚠️ 这是**起点值**，需按批次 1 的实机信号校准；若实机满级 >10 分钟，下调系数到 12。

### 批次 2 — 敌血联动分级（保留雪球，但加合理代价）

```yaml
current_rung: UL-L1
released_this_round:
  - variable: "CFG.LEVEL.diffLv：0.03 → 0.05（仅普通怪，Boss/守卫另有血量公式不受影响）"
    reason: "批次 1 归因明确后，补上行业标准的等级负反馈；探针显示单独调它杠杆中等"
    expected_learning: "杀怪率增速放缓，成长代价可感知但不破坏爽感"
held_constant:
  - "批次 1 定稿的 xpNext 公式不动"
  - "SPAWN / UNLOCK_TABLE / 波次不动"
  - "diffTime=0.004 不动"
  - "武器被动不动"
preregistered_signals:
  pass: ["实机满级时间仍在 8-10 分钟带内", "玩家反馈'变强有代价但不憋屈'"]
  fail: ["满级时间 >12 分钟", "或玩家反馈'越打越吃力'"]
  confounded: ["同期动了经验曲线或刷怪"]
  stop: ["普通怪血 >3 倍导致前期卡关"]
rollback: "diffLv 还原为 0.03"
stop_rule: "出现前期卡关立刻停"
```

### 批次 3 — 决策引擎续航（治"满级后无卡"）

```yaml
current_rung: UL-L2
released_this_round:
  - variable: "满级后经验处理：从'转微量回血'改为'Limit Break 式超额升级'"
  - variable: "HUD 等级显示：满级后显示 LB 层数而非 LV20"
    reason: "前两批解决'冲太慢'，本批解决'冲完就没事干'；两者是独立问题，放一批因同属决策引擎"
    expected_learning: "满级后决策不再断供，玩家继续有构筑成长"
held_constant:
  - "批次 1/2 定稿的曲线与敌血不动"
  - "关底触发时机不动（仍满级触发）"
  - "卡池内容不动（内容扩展是另一个项目）"
preregistered_signals:
  pass: ["满级后每 ~30 秒仍有 1 次超额升级卡", "关底战期间构筑仍在成长"]
  fail: ["超额升级导致关底被秒杀（构筑膨胀过头）"]
  confounded: ["同期扩了卡池"]
  stop: ["出现无限升级/内存泄漏"]
rollback: "恢复'满级转回血'逻辑"
stop_rule: "出现 stop 立刻停"
```

## 5. Transfer Checks（每批都要过）

| 项 | 检查 |
|---|---|
| `near` | 同类系统（其他关卡）是否同步受益？→ 曲线是全局公式，20 关同步生效 ✅ |
| `medium` | 相邻系统是否被连带？→ 曲线影响关底出场时机（满级触发），需确认关底血量仍撑得住 40-90 秒 |
| `far` | 能否迁移到别的幸存者项目？→ 分段线性曲线是通用旋钮，可迁移 |
| `negative_transfer` | **哪里会变差？** → ① 满级变慢意味着单局变长，移动端续航/发热；② 前期升级变稀可能让首局更枯燥，需靠波次新面孔补偿（第二项目"内容扩展"） |

## 7. 开放问题（需老大拍板）

1. **单局时长目标确认**：8-10 分钟是设计稿写的，但你试玩的真实体感是多少？若你其实想要 5-6 分钟一关，批次 1 的目标公式要下调。
2. **"加油门"还是"踩刹车"**：本方案选择拉长成长过程（慢升级）。另一种路子是保持 2-4 分钟满级但让关卡更短、更像街机——这是品类定位问题，不是数值问题。
3. **内容扩展的耦合**：曲线拉长后，5 分钟前无新怪的问题会更明显（原本 5 分钟就满级，现在是 5 分钟才到中段）。**强建议**：批次 1 落地时同步把波次投放拉长（`WAVE_TIME` 从 4 个点到 8 个点），否则"空"的感觉会从后半段挪到中段。此项已记入待办，但本轮因单变量纪律不并入批次 1。
